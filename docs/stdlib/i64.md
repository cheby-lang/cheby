# `std::i64`

The module of the built-in `I64` type, a signed 64-bit integer (§3.3.3, D-105). `I64` is in the prelude (D-112), and this module is where the type is declared (§8.2):

```cheby
pub type I64
```

An `I64` holds the integers from −2⁶³ (−9223372036854775808) to 2⁶³−1 (9223372036854775807). Arithmetic is checked at that width, so a result outside the range panics (D-025). `I64` is exact on JS too, where it is a `BigInt`, so it behaves the same on every target, although its arithmetic is slower there than `Int`'s (D-106, ADR-0030).

The functions of this module are the integer families of [Numeric modules](README.md#numeric-modules), which define them for every integer type. The table below lists each function with its signature and family, and the examples show one family each (D-350). `compare`, `show` and the arithmetic functions make `I64` satisfy `Compare`, `Show`, `Add`, `Sub`, `Mul`, `Div` and `Neg` (§8.7, §8.8).

There is no conversion from `Float` or `F32`. A float becomes an `I64` through a rounding function such as `float::truncate` and then `i64::from_int` (D-359). The conversions from `I64` to other types are in their modules, such as `int::from_i64` and `float::from_i64`. The bitwise operators are built in (§5.4.6), so there are no functions for them, and the functions `std::int` has outside the families are not repeated here (D-389, D-391).

`i64::from_int` is widening, because every `Int` is an `I64`, but `int::from_i64` is narrowing on every target, because it can fail on JS (ADR-0030).

Every function costs O(1), except `parse` and `parse_base`, which cost O(n) in the length of the text. The costs are informative.

## Examples

### Constants

```cheby
test "the i64 range" {
  assert i64::min_value == -9_223_372_036_854_775_808
  assert i64::max_value == 9_223_372_036_854_775_807
}
```

### Conversions

```cheby
test "conversions to i64" {
  assert i64::from_int(-42) == -42
  assert i64::from_u32(4_294_967_295) == 4_294_967_295
  assert i64::from_u64(42) == Ok(42)
  assert i64::from_u64(u64::max_value) == Err(Nil)
  assert int::from_i64(i64::from_int(-42)) == Ok(-42)
}
```

### Parsing and text

```cheby
test "i64 parses and shows decimal digits" {
  let small: I64 = -5
  assert i64::parse("-9223372036854775808") == Ok(i64::min_value)
  assert i64::parse("9223372036854775808") == Err(Nil)
  assert i64::parse_base("7fffffffffffffff", 16) == Ok(i64::max_value)
  assert i64::show(i64::max_value) == "9223372036854775807"
  assert "{small}" == "-5"
}
```

### Comparison

```cheby
test "comparing i64 values" {
  assert i64::compare(-1, 1) == Less
  assert i64::compare(3, 3) == Equal
  assert i64::min(-100, 7) == -100
  assert i64::max(-100, 7) == 7
}
```

### Arithmetic

```cheby
test "i64 operators as functions" {
  assert i64::add(100, 27) == 127
  assert i64::sub(-100, 28) == -128
  assert i64::mul(-4, 5) == -20
  assert i64::div(-7, 2) == -3
  assert i64::rem(-7, 2) == -1
  assert i64::neg(127) == -127
  assert i64::abs(-127) == 127
}
```

### Checked arithmetic

```cheby
test "i64 checked arithmetic reports overflow" {
  assert i64::checked_add(100, 27) == Ok(127)
  assert i64::checked_add(i64::max_value, 1) == Err(Nil)
  assert i64::checked_sub(i64::min_value, 1) == Err(Nil)
  assert i64::checked_mul(i64::max_value, 2) == Err(Nil)
  assert i64::checked_div(i64::min_value, -1) == Err(Nil)
  assert i64::checked_rem(7, 0) == Err(Nil)
  assert i64::checked_neg(i64::min_value) == Err(Nil)
}
```

### Wrapping arithmetic

```cheby
test "i64 wrapping arithmetic wraps around" {
  assert i64::wrapping_add(i64::max_value, 1) == i64::min_value
  assert i64::wrapping_sub(i64::min_value, 1) == i64::max_value
  assert i64::wrapping_mul(i64::max_value, 2) == -2
  assert i64::wrapping_neg(i64::min_value) == i64::min_value
}
```
