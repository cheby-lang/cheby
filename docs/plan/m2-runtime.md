# M2: Runtime

Goal: Perceus, fibers on an M:N scheduler, structured concurrency, channels, selectors, cancellation, unwinding and non-blocking IO, so that every concurrent example runs on the JIT (D-099, step 2).

Prerequisites: M1 done. Tier-2 stdlib specified. OQ-P7 (context switch) and OQ-P8 (poller) settled. All three are met: the tier-2 modules are specified in `docs/stdlib/` (D-645), D-676 settles OQ-P7 and D-680 settles OQ-P8.

Out of scope: sockets, which arrive with `std::net` in M3 (D-681); comparing generated programs with a reference evaluator (M3, D-719); drop functions of user external types and `@blocking` foreign code from packages, which wait for OQ-P9 in M3 (D-647, D-683, D-703); fibers on Windows (M6, D-714); the `.mjs` files of the tier-2 modules (M4, D-661); io_uring (D-680); and the optimizations of D-731, each of which needs benchmark data and an entry of its own.

The design behind the tasks is logged in the [M2 design](../decisions/LOG.md#2026-10-11-m2-design) session, D-645 to D-732. [architecture.md](architecture.md#3-runtime) describes the runtime it builds.

## Packages

The work is split into packages. A package starts once the packages it depends on are merged, and packages that own disjoint files run in parallel.

```text
Lane 0 (first):       D0, H0, P0, U1a       baseline before any change; variants before the scheduler
Lane A (core):        S1 ─┬─> S5 ──> S6     the slice, up to checkpoint 1
Lane B (stacks):      S2 ─┘
Lane C (handles):     (after S1) S3 ──> S6
Lane D (front end):   (after U1a) S4 ──> S6
Lane E (codegen):     (after S1) G1
Lane F (unwinding):   (after U1a) U1b ──> one tree: U2a, U2b, U3, measured ── checkpoint 1 ──> U4 ──> U5 ─┬─> T1
                                                                                                          └─> L1 ──> L2, T4
Lane G (IO):          (after S4, U4) I1 ;  (after L1, T1, I1) H1
Lane H (Perceus):     P0 ──> (after U1b) P1 ──> P2 ──> P3, P4 ;  P5, P6 at any time
Lane I (collections): Q1 at any time, its second benchmark after P2
Lane J (follow-ups):  (after U4) C1, C2 ;  (after U5) S7 ;  (after C1) U6 ;  F1 at any time
```

- **Vertical slice (checkpoint 1).** D0, H0, P0's baseline, U1a, S1 to S6 and G1. At checkpoint 1, `005_prime_sieve` runs on the JIT with real fibers on the M:N scheduler and real channels. Its run trial and its `::test` trial pass with `CHEBY_THREADS` unset, 1 and 2, with the leak check at zero, and so does 028's run trial, whose `main` starts no fiber. Every M1 test stays green on Linux and macOS, and Windows builds.
- **The unwinding backend is chosen at checkpoint 1.** U2a and U2b are built in one tree with the slice, both over U1b's MIR pass and with U3, behind the hidden switch `CHEBY_UNWIND=off|flag|try_call`, whose default `off` keeps M1's behavior (D-742). That gives one binary and one MIR pass for the measurement of D-702. The user chose return-flag propagation at checkpoint 1 (D-696, D-733). U4 made it the default, deleted the `try_call` prototype and removed `CHEBY_UNWIND`; `CHEBY_UNWIND_EDGES=off` stays as the measurement switch (D-770).
- **Slice+ (checkpoint 2).** Unwinding and cancellation make 018 (a worker's panic becomes its scope's `Err`), 028's tests (a panic caught by `scope`) and 022 pass. Reached at `00f69d4` (Status).
- **Checkpoint 3.** T1, L1, U6, P1, P5 and P6: 009, 013 and 019 pass, so every M2 example runs, borrowing is on, and large literals compile in linear time. Reached at `2ae8eff` (Status).
- **Checkpoint 4.** I1, L2, T4, S7, P2 to P4, Q1 and F1, run as two sub-checkpoints with a review between them: 4a (I1, L2, T4, S7 and F1) and 4b (P2 to P4 and Q1). 4a is reached at `a5ac467` and 4b at `efb067e` (Status).
- **Checkpoint 5.** H1 and checkpoint 4b's two follow-ups: deadlock detection with its locations, the sanitizer and Miri jobs, the serial group, the slot cache's verdict and fusion's bound. Reached at `33dbaf8` (Status).
- **Critical paths.** To the slice: S1, S5 and S6 in sequence, with S2 beside S1, and U1a then S4 beside both. To M2's exit: checkpoint 1, U4, U5, then T1 and L1, then L2 and T4, beside P1, P2 and P4 and the sanitizer workflow. C1 and C2 follow U4, S7 follows U5, and U6 follows C1, none of them on the critical path.
- Until U4 merged, a panic in a child fiber was a fatal runtime error and a root's panic was reported as in M1. This interim never shipped, was not logged, and U4 removed it (Status).
- **H1's two open questions are settled.** The locations in the deadlock report (OQ-10-11, given D-732) are settled by D-856, and the detection of a deadlock in one test while others run (OQ-13-8) by D-857, both logged before H1's code.

## Exit criteria
