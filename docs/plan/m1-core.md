# M1: Single-fiber core

Goal: the whole front end, the MIR with naive reference counting, the Cranelift JIT and the runtime kernels, enough to check every example whose standard-library modules exist with `cheby check` and run every example that needs no fibers through `cheby run`, `cheby test` and `cheby repl` (D-099, step 1). Examples that import modules of later tiers are checked from the milestone that ships them (D-477).

Prerequisites: M0 done. Tier-1 stdlib specified. The value representation (D-278, D-279), syntax tree (D-280) and hash function (D-281) are settled.

Out of scope: fibers, channels and scopes (M2), unwinding (M2: a panic ends the process, or abandons the REPL entry per D-283), Perceus borrowing and reuse (M2), AOT and the disk cache (M3), JS (M4).

## Phases

The tasks are grouped into phases. Phases overlap: a later phase can start once the tasks it depends on are done, not when the whole earlier phase is.

```
A syntax ─► B names ─► C types ─► D MIR ─► E codegen ─► G driver and CLI
                                     ▲            ▲
                         F runtime kernels ───────┘
H stdlib tier 1 (Cheby parts) starts once C can check it
I measurement runs from the first end-to-end program
```

## Exit criteria

M1 is judged on Linux and macOS. On Windows, CI builds the workspace and runs the unit tests, and the harnesses skip the UI run tests, the conformance runs and `::test` trials and the REPL suite until M6 (D-545). Every criterion is checked with `CHEBY_MILESTONE=M2`, so the tests of M1 count as required before `tests/milestone` is bumped (D-544).

- These examples pass through `cheby run` with their goldens: 001, 002, 003, 004, 006, 007, 008, 010, 012, 014, 015, 016, 017, 021, 023, 024, 025, 026, 027, 029, 032, and 011, which passes since gate 5 of the back end.
- Every other example passes `cheby check` for both targets, with two exceptions. Examples with dependencies are checked from M5, when dependencies resolve, and 030 is the only one (D-446). Examples that import standard-library modules of later tiers are checked from the milestone that ships those modules, and until then report only E0038 for those imports: 005, 009, 013, 018, 019, 022 and 028 from M2, and 031 from M3 (D-477). The examples that pass `cheby check` at M1 exit are therefore 001-004, 006-008, 010-012, 014-017, 020, 021, 023-027, 029 and 032.
- All tier-1 stdlib modules are implemented on native, except `std::multimap`, `std::sorted_*` and `std::ordered_*`, which are still unshipped at M1 exit (D-480).
- The leak counter reports zero live objects at exit for every passing example (D-458).
- E0038 is emitted only for imports of standard-library modules that are planned but not shipped, and its explanation says so (D-480). MIR lowering reports none, and a construct it cannot lower is an internal compiler error (D-554).
- Every warning of §13.8 and every "must" of chapters 2 to 8 that M1 implements has a UI test.
- The REPL test suite passes.
- The `test` blocks of the examples above pass through `cheby test` in the conformance suite (D-472).
- Builds are deterministic across thread counts.
- Compile-speed numbers are reported, and OQ-P10, the throughput budget, is settled.

### Back end

The back end starts from a plan whose spec gaps are settled by D-520 to D-554, logged in the [M1 back-end plan](../decisions/LOG.md#2026-10-10-m1-back-end-plan) session before its first wave. Codes E0075 to E0078 are added for constant evaluation (D-533). OQ-P10 is an open item of that session.

Wave 1 (MIR contracts, the runtime ABI, code generation for every MIR form, numbers and lists) is done at commit `c029c49`. The gaps it found are settled by D-555 to D-568, logged in the [M1 back end, wave 1](../decisions/LOG.md#2026-10-10-m1-back-end-wave-1) session. Changes against the plan:

- `cheby_rt_equal` takes the location of the `==` or `!=` as a fourth argument, so a panic on a function value reports where the comparison is written (D-556).
- No pure-Rust port of CORE-MATH passed D-553's verification, so `float::pow`, `exp`, `ln`, `sin`, `cos`, `tan` and `atan2` are written in Rust with double-double evaluation and Ziv's rounding test, by tasks W4-D and W5-D, with no C compiler in the build (D-568). Until each one passes the verification, it is not registered.
- Running `Const::BuiltinDesc` waits for the runtime's `cheby_rt_desc_*` objects in wave 3.

Wave 2 (scalars, operators, panics, patterns, closures, records, strings and I/O) is done at commit `0bbab0a`. Examples 001, 002, 003, 004 and 008 run with their goldens and pass the leak check under `CHEBY_RT_POISON=1`. The gaps it found are settled by D-569 to D-578, logged in the [M1 back end, wave 2](../decisions/LOG.md#2026-10-10-m1-back-end-wave-2) session. Changes against the plan:

- THIR's float literal holds its text rounded once to `Float` and once to `F32`, and constant evaluation (W3-D) and the REPL (W4-B) read the value of the literal's type instead of narrowing the `Float` one (D-569).
- Closures inside a test are named by the test's ordinal, `cb$clo$test$<module path>$<ordinal>$<n>`, because a test's name collided with an item's (D-572).
- The runtime gains `entry::set_program`, which `cheby test` and the REPL call before their entries run, and `io::read_input_line`, through which the REPL reads its lines (D-575, D-578). What `env::program_name` and `env::args` return in a REPL session was an open item of the wave-2 session, which D-612 settles.

Wave 3 (dictionaries, equality and hashing, maps and sets, constant evaluation and `cheby test`) is done at commit `76b2cc6`. 19 of the 32 examples run with their goldens and pass the leak check under `CHEBY_RT_POISON=1`, on macOS and in a Linux container: 001, 002, 003, 004, 006, 007, 008, 010, 011, 014, 015, 017, 023, 024, 025, 026, 027, 029 and 032. `cheby test` passes for each of them and for 012. `cargo xtask test-std` reports 337 passed, 0 failed and 31 that do not build, all with E0053: the tests of `std::bytes`, of the float functions of D-568 and four `io` and `string` tests that reach `Bytes`. `Const::BuiltinDesc` now runs against the runtime's `cheby_rt_desc_*` objects. The gaps the wave found are settled by D-579 to D-601, logged in the [M1 back end, wave 3](../decisions/LOG.md#2026-10-10-m1-back-end-wave-3) session. Changes against the plan:

- Static object symbols end the module path with `$$`, because D-523's form let two modules produce one symbol, and a JIT now rejects a static defined again with different contents (D-579). A REPL redefinition must therefore give the statics it changes new symbols, which D-611 settles, and the descriptor of `dyn Show`, whose module path is empty, keeps the general form (D-603).
- Every `@std_hooks` hook of a module with a code unit is compiled, because keying hooks to constructor mentions broke every program that imports `std::io` (D-585).
- Maps and sets nested in each other compare, hash and print on the walk's worklist (D-586). Keys whose full 64-bit hashes are equal in a HAMT collision node are still compared in a nested walk, which a random seed makes vanishingly rare.
- A function with only a JS implementation stays in the native program and panics, so a constant that reaches it gets E0077 instead of an internal compiler error (D-591).
- `cheby test` and the std self-test select only the tests that exist on native (D-597), and each test runs on a 64 MiB stack, like `main` (D-596).
- The `cheby` command runs on a thread with a 256 MiB stack, because the decision trees of list patterns recurse about six frames per tested element (D-601). It is a stopgap until W5-C and W6-A give the decision-tree builder an explicit stack.

Wave 4 (`dyn` values, the REPL session, constant collections and limits, `Bytes` and float math, flags and the parallel front end) is done at commit `1a3b0f0`. 22 of the 32 examples run with their goldens and pass the leak check under `CHEBY_RT_POISON=1`: those of wave 3 and 012, 016 and 021. `cargo xtask test-std` builds every std module and reports 368 passed and 0 failed. 14 REPL transcripts pass, and `cargo xtask check-determinism` finds all 37 projects identical. The gaps the wave found are settled by D-602 to D-623, logged in the [M1 back end, wave 4](../decisions/LOG.md#2026-10-11-m1-back-end-wave-4) session. Changes against the plan:

- A `dyn` forwarder is keyed by the interface function and by the receiver's interface, because a function's field differs between the dictionaries of the two interfaces (D-602).
- REPL entries are modules `<repl:N>` of the local package, checked for `native` only (D-606). A redefinition takes over a slot only with an equal type signature (D-607), and session items and the statics that entries build use the module path `<repl>`, with generations counted per name and per text (D-611).
- By the user's decision, a prompt-level `let` rebinding shadows (D-608), and the prompt entries count as one module for interface satisfaction (D-610). Both are implemented in W5-A. Until then the code stores a same-type `let` rebinding into the old slot, checks the readers of a `let` again when its type changes, and no type entered at the prompt can satisfy a non-empty interface.
- The memory limit of constant evaluation counts only what one top-level evaluation keeps live, checked before each allocation, because a count over the whole build made a constant's verdict depend on the constants before it (D-617).
- `-j` is a global option that sizes rayon's worker pool, whose workers get 256 MiB stacks like the command's own thread (D-622).
- The fast phase of the correctly rounded functions reads generated tables instead of computing them at the first call, and Ziv's loop stops at 2048 bits (D-623).

Wave 5 (the REPL commands and `:reload`, the standard library's own tests, every example through the back end, parallel code generation, explicit stacks for patterns and runtime performance) is done at commit `ab1cf98`. The 22 examples of wave 4 run with their goldens and pass the leak check under `CHEBY_RT_POISON=1`, on macOS and in a Linux container, and `cheby test` passes for each of them. 011 is among them, so H4 is done and 011 stays on M1's exit list. Gate 5 also ran the 22 examples 1,100 times on each platform without the empty output of review R4-8, and confirmed on Linux that an abandoned entry's stack is released (R4-5). The gaps the wave found are settled by D-624 to D-637, logged in the [M1 back end, wave 5](../decisions/LOG.md#2026-10-11-m1-back-end-wave-5) session. Changes against the plan:

- The REPL commands, `:reload` and the stale marker are specified (D-624 to D-626). `:reload` checks again every definition that uses any earlier version of a reloaded module, and a rejected reload changes nothing (D-625).
- Session functions satisfy interfaces for session types through forwarders in each type's entry module, with no change to the checker or code generation (D-627). D-608 and D-610 are now implemented.
- Entries of a package whose targets lack `native` are still checked for `native`, so a `js`-only package's portable items work at the prompt (D-628).
- The spec tests that need a module importing their own live in that module, and helper items of std tests are named by a written path (D-630, D-631).

- The usefulness search and the decision trees use explicit stacks, so D-601's stopgap is no longer needed for list patterns. The 256 MiB stacks stay as a margin for passes that still recurse (D-633).
- An owned list slice at a list's last use makes a walk over `[x, ..rest]` allocate nothing per step, and with the other runtime fixes, 004's `cheby test` went from 9.4 s to 2.4 s (D-634). `CHEBY_RT_STATS` shows the runtime's counters (D-635).
