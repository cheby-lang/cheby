# E0054: native symbol bound with two different C signatures

Every `@external(native, "symbol")` in a program that names the same C symbol must give it the same C signature (§12.5.1, D-455). The C signature follows from the Cheby parameter and result types: a `String` is a pointer, `Int` is a 64-bit integer, a `Nil` result is `void`, and so on. Two declarations that disagree would call one C function in two incompatible ways, so the second one is reported, with the first as a note. This holds across every module and package of the program, the standard library included.

Example:

```cheby
@external(native, "store_open")
fn open(path: String) -> Int

@external(native, "store_open")
fn open_named(path: String, name: String) -> Int
```

Declare the C function once and call it from both places, or give the two declarations the same parameter and result types:

```cheby
@external(native, "store_open")
fn open(path: String) -> Int

fn open_named(path: String, name: String) -> Int {
  open(path)
}
```
