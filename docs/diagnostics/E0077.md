# E0077: constant whose evaluation reached an external function or effect it may not use

Constant evaluation must give the same value on every build, so an initializer may not perform input or output, read the environment, the clock or randomness, or call foreign code (§4.5, §13.9, D-090). Effects are not tracked by types (D-016), so this is found while the constant is evaluated: reaching any `@external` function is an error, except the effect-free kernels of `std::list`, `std::map`, `std::set`, `std::string`, `std::bytes` and the numeric modules `std::int`, `std::float`, `std::f32` and the sized integer modules (D-360, D-537), and `std::option`'s one kernel, `panic_at`, which only panics. So a failing `option::expect` or `result::expect` in a constant is E0075, not this error (D-1660). The error points at the constant whose initializer reached the function, which may be a constant that the first one read, and a note names what evaluation reached: "it reached the external function `<symbol>`; only the kernels of `std::list`, `std::map`, `std::set`, `std::string`, `std::bytes` and the numeric modules run at compile time". The note leaves out `std::option`, whose kernel a program never calls itself. `<symbol>` is the native symbol, such as `cheby_io_println`, or the path of a function that has only a JS implementation, which a constant that exists on `js` may call (§12.5, D-591, D-592).

The modules of the runtime follow the same rule. Every function of `std::duration` and the seeded functions of `std::random` (`from_seed`, `next_int_between` and `next_fraction`) are written in Cheby with no kernel, so they run in constants (D-650, D-656). The host functions of `std::random` (`int_between`, `fraction` and `from_host`) first call the `@std_context` kernel `cheby_random_sys_stream_on`, which looks for a seeded stream in the fiber's context, before they draw from the stream or from the kernel `cheby_random_host_bits`, so a note names `cheby_random_sys_stream_on`, and `random::with_generator` reaches `cheby_random_sys_stream_push` (D-1048, D-1574). The functions of `std::runtime` are kernels, and `std::fiber`, `std::channel` and `std::selector` are built on kernels that use the running fiber (`@std_context`). None of these kernels runs in constants, so a constant whose evaluation reaches one is this error (D-656, D-657, D-692). In `std::time`, `now` and `monotonic` call the `@std_context` kernels `cheby_time_sys_now_unless_provided` and `cheby_time_sys_monotonic_unless_provided`, which look for a clock in the fiber's context, and `elapsed` and `until` call `monotonic`, so a note names one of these two. `sleep` reaches `cheby_time_sys_sleep`, and `sleep_until` reaches `cheby_time_sys_monotonic` first. The clocks themselves are plain data, and `time::now_on` of a fixed clock runs in constants (D-1570, D-1597).

`cheby check` also reports this error when a constant calls a native function that nothing in the build defines, because it cannot run it (D-532). The note then says "it called a native function that nothing in this build defines" (D-592). `cheby check` reports nothing for such a function that constants never call; `cheby run` reports it as E0053.

Example:

```cheby
import std::io

const greeting: String = announce("hello")

fn announce(text: String) -> String {
  io::println(text)
  text
}
```

Compute the value without the effect, and perform the effect at run time:

```cheby
import std::io

const greeting: String = "hello"

fn main() {
  io::println(greeting)
}
```
