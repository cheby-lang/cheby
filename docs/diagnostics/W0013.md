# W0013: negative integer literal passed as a standard-library count argument

Standard-library functions clamp count, width and length arguments that are out of range, so `list::take(xs, -1)` is `[]` and does not panic (D-298). A negative literal written for such an argument is almost always a mistake, often an index counted from the end as in other languages, so the compiler warns. The warning applies only to a literal written in the call, not to constants or computed values (D-303). A literal in a capture, such as `list::take(_, -1)`, is a literal written in the call too (D-518). The parameters are those that the standard library marks with `@std_clamped` (§4.8, D-482). Besides the counts of the collections and strings, they include the capacity of `channel::new`, where a negative capacity counts as 0 (D-672), the `stack_bytes` of `fiber::spawn_with_stack` (D-659) and the `count` of `runtime::set_thread_count` (D-657).

Example:

```cheby
import std::list

fn all_but_last(xs: List<Int>) -> List<Int> {
  list::take(xs, -1)
}
```

Compute the count you mean:

```cheby
import std::list

fn all_but_last(xs: List<Int>) -> List<Int> {
  list::take(xs, list::length(xs) - 1)
}
```
