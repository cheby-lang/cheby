# E0012: invalid string interpolation

Inside a string literal, `{` starts an interpolation that ends at the next `}`. Between the braces only a name is allowed, optionally followed by field names and then `:?`, with no spaces (§2.5.4, D-115):

```cheby
"hello {name}"
"at {point.x}, {point.y}"
"debug: {state:?}"
```

Anything else, such as an expression, a tuple position or an empty `{}`, is an error, and so is a `{` without its `}`. An interpolation must also fit on one line: a line break ends it, so a `}` on the next line does not close it.

A string inside the braces, as in `"{f("x")}"`, is read as a string when it closes on the same line and a `}` follows it there. The interpolation then ends at that `}`, and this error is the only one reported for it (D-1656). A `"` with no `}` after its string on the line ends the interpolation and the string, as in `"price {"`, which is an unclosed interpolation.

When the interpolation starts with such a string, as in `"price {" + amount + "}"`, the `{` was almost always meant as a literal brace, so the help says that `\{` writes one instead of suggesting a name (D-1661). Write `"price \{" + amount + "}"`, or interpolate the name: `"price \{{amount}}"`.

Example:

```cheby
fn label(count: Int) -> String {
  "next: {count + 1}"
}
```

Bind the value to a name first:

```cheby
fn label(count: Int) -> String {
  let next = count + 1
  "next: {next}"
}
```

To write a literal brace, escape it as `\{`. A closing `}` needs no escape.

A test's name allows no interpolation at all, because it is fixed text (§4.7, D-055, D-495): `test "{subject} works" { … }` is an error. Write the name out, or escape the brace as `\{`.
