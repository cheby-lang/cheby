# E0069: constants that refer to each other in a cycle

Constants may refer to other constants, but not cyclically, since each one is evaluated from the others at compile time (§4.5). The front end reports a cycle of constants of one module that name each other directly in their initializers. Imports are acyclic, so no cycle crosses modules, and a cycle through a function call is found when the constants are evaluated (D-478, D-511). The message lists the constants in the cycle.

A cycle through a function call is found while the constants are evaluated (D-511, D-535): when an initializer needs the value of a constant whose evaluation is still in progress, such as its own value through a function that reads it, evaluation stops, and the error points at that constant's name with the label "`a` needs its own value while it is computed" (D-533). `cheby check` and `cheby run` both report it. The constants that the failed one was computing for are not reported again, so a cycle `a` → `b` → `a` gives one error (D-592). When only constants in cycles are left to evaluate, the first by module order and then by name is evaluated next, and the error points at the constant that its evaluation finds in progress (D-594).

Example of a cycle through a function call:

```cheby
const limit: Int = twice_limit() / 2

fn twice_limit() -> Int {
  limit * 2
}
```

Compute the value from something that does not need it:

```cheby
const limit: Int = twice_limit() / 2

fn twice_limit() -> Int {
  200
}
```

Example:

```cheby
const width: Int = height * 2
const height: Int = width / 2
```

Give one of the constants a value that does not depend on the other:

```cheby
const width: Int = height * 2
const height: Int = 10
```
