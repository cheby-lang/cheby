# E0056: space between `-` and the number of a negative literal

A negative literal is written with the `-` directly before the digits: `-5`, `-128`, `-0.5` (§5.3.1, D-470). Anything between the `-` and a number literal is an error, in expressions and in patterns. When the gap is spaces and tabs, the help line suggests removing it.

Inside `(`, `[` and type `<…>`, a line break is whitespace (§2.8), so the gap may also hold line breaks and `//` comments, as in `f(- // lowest` followed by `5)` on the next line. The message then says "whitespace or a comment", and the help offers no fix, because deleting the gap would delete the comment. Outside brackets, a line break after a `-` that has no left operand is a syntax error (E0014), since a line does not continue after it.

Binary minus is not affected: `a - 5` subtracts. Neither is negation of a parenthesized expression: `-(5)` negates `(5)`.

Example:

```cheby
fn sign(n: Int) -> Int {
  case n {
    - 1 => - 1
    _ => 1
  }
}
```

Write the `-` next to the number:

```cheby
fn sign(n: Int) -> Int {
  case n {
    -1 => -1
    _ => 1
  }
}
```
