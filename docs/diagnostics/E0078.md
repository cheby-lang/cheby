# E0078: constant that exists on `js` and holds an `Int` outside the JS safe range

On JavaScript, `Int` is limited to the safe-integer range, from -(2^53 - 1) to 2^53 - 1 (D-037). A constant's value is computed once, on the host, so its initializer may compute larger numbers, but a constant that JavaScript code can read must hold only representable `Int` values, anywhere in its value (§4.5, D-540). A constant exists on `js` when its targets, intersected with the package's `targets`, contain `js`. Constants that exist only on native, such as `int::max_value` or a constant with `@target(native)`, are never checked (D-358, D-540). Only `Int` values are checked: `I64` and `U64` are exact on JavaScript, where they are `BigInt`s (§12.4), so a constant of those types may hold any value of its type. The error points at the constant's name, and a note gives the value found.

Example, in a package whose `cheby.toml` has `targets = ["native", "js"]`:

```cheby
const big: Int = 9_007_199_254_740_991 * 2
```

Keep the value in range, or make the constant exist only on native:

```cheby
@target(native)
const big: Int = 9_007_199_254_740_991 * 2
```
