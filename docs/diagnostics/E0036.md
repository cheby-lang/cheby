# E0036: invalid `cheby.toml`

The package manifest could not be used (§13.3). It must be valid TOML, and:

- `name` is the package name, a `snake_case` identifier other than `std`,
- `version` is a semantic version such as `0.1.0`,
- `targets`, if present, lists `"native"` and/or `"js"`, at least one and none twice,
- `kind`, if present, is `"program"` or `"library"` (D-1851),
- no other top-level keys appear than `name`, `version`, `description`, `licences`, `kind`, `targets`, `[dependencies]`, `[overrides]`, `[const-eval]`, `[runtime]` and `[native]`, and a dependency has only `git`, `tag` and `rev`, or only `path` (D-444, D-660, D-940, D-1856),
- a `git` URL is `https://host/path`, `ssh://git@host/path` or `git@host:path`, a `tag` is the name of a git tag, and a `rev` is at least seven digits of a commit's hash (D-1879),
- `[overrides]`, if present, maps git URLs to `{ path = "…" }` (D-1865),
- the `path` of a dependency is relative to the directory of this manifest, with `/` between names, and names a directory that holds a `cheby.toml` (D-1862),
- `[const-eval]`, if present, is a table with only `time-limit`, a string holding an integer greater than zero followed by `ms` or `s`, such as `"10s"`, and `memory-limit`, a string holding an integer greater than zero followed by `KiB`, `MiB` or `GiB`, such as `"1GiB"` (D-536). The integer is decimal digits, leading zeros allowed, and the limit in milliseconds or bytes must fit in 64 bits. A limit of zero is an error, not "no limit" (D-616).
- `[runtime]`, if present, is a table with only `fiber-stack` and `main-stack`, the default stack reservations of fibers and of the root fiber. Each is a string of the same form as `memory-limit`, such as `"16MiB"`, from 1 MiB to 16 GiB (D-660). A dependency's `[runtime]` table has no effect, but it is checked the same way.
- `[native]`, if present, is a table with only `sources` and `libraries`, each a list of strings (D-940). An entry of `sources` is the package-relative path of a C file, never an absolute one: it ends in `.c`, names a file that exists, not a directory, and stays inside the package once `..` and symbolic links are resolved. A `..` that leaves the package is reported as outside it even when no such file exists (D-1200). An entry of `libraries` names a system library the way the linker takes it after `-l`, such as `"sqlite3"`: a non-empty string of letters, digits, `_`, `-`, `.` and `+`. A package whose `targets` leave out `"native"` must not have the table. The table is how a package supplies native code (§12.5.4). Every command checks it, `cheby check` included, but only commands that run or build code compile the C files.

The message names the problem. A dependency must be a library (D-1854) and target what its user is checked or built for (D-1867). One directory holds each name and major in a build (D-1857), and packages must not depend on each other in a cycle (D-1864). These are reported at the dependency's key. A git dependency must be in `cheby.lock` as the manifest requires it, which `cheby update` sees to, and downloaded, which `cheby fetch` does (D-1881).

Example:

```toml
name = "MyApp"
version = "1"
```

Use a `snake_case` name and a full version:

```toml
name = "my_app"
version = "0.1.0"
```

Another example, a `[native]` table that lists a header in `sources` and two libraries in one string:

```toml
name = "sqlite"
version = "0.1.0"

[native]
sources = ["src/sqlite_ffi.c", "src/sqlite_ffi.h"]
libraries = ["sqlite3 m"]
```

List only the C files that are compiled, since the compiler finds headers through `#include`, and give each library its own string:

```toml
name = "sqlite"
version = "0.1.0"

[native]
sources = ["src/sqlite_ffi.c"]
libraries = ["sqlite3", "m"]
```
