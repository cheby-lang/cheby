# E0055: native symbol reserved for the toolchain

An `@external(native, …)` outside the standard library must not name a C symbol that belongs to the toolchain (§12.5, D-455, D-944). These are:

- the runtime's internal functions and data, which start with `cheby_rt_`,
- generated functions, slots and constants, which start with `cb$`,
- every other name the runtime exports: the standard library's kernels, such as `cheby_list_length` and `cheby_float_sin`, and the `cheby_ffi_` functions of `cheby.h` (§12.5.1, D-945).

These symbols have signatures and rules that only the compiler knows. Binding one would also behave differently by command: `cheby run` binds the name to the runtime, while the linker of `cheby build` would find two definitions, or pick one of them by archive order (D-944).

Other names that start with `cheby_`, such as `cheby_sqlite_open`, stay free (D-455). A new toolchain that adds a kernel reserves its name as well, so an upgrade can turn a binding that worked into this error, which names the clash. Rename your C function then.

A binding of a name the runtime exports is reported with this code alone, never also as E0054 against the standard library's binding of the same symbol (D-1204). A package's C code that defines a reserved name is reported too, as a tool error before anything is linked or loaded, not with this code (D-944).

Example:

```cheby
@external(native, "cheby_rt_drop")
fn release(text: String)
```

Bind your own C function instead, with a name that the toolchain does not use:

```cheby
@external(native, "store_release")
fn release(text: String)
```
