# E0045: unknown, malformed, duplicated or misplaced attribute

The set of attributes is fixed (§4.8, D-200, D-461): `@external`, `@target`, `@blocking`, `@async` and `@deprecated`, plus the inner attribute `@!target` for a whole module. This error reports an attribute with an unknown name, with the wrong arguments, given twice, or placed on an item it does not apply to. Only items take attributes: a run of attributes on a variant, a record field or an interface function is also this error, reported once by the parser (D-514). `@external` may appear once per target (§12.5). It also reports an item that exists on no target: a `@target` that contradicts the module's `@!target`, or a function without a body whose `@external` attributes miss every target left to it (§12.6, D-513). And it reports a bound on a type parameter of a function with an `@external`, with or without a body, at the bound: a bound passes a function package and a type descriptor, which have no foreign ABI (§12.5, D-207, D-554).

The standard library's own attributes, `@std_clamped`, `@std_hooks`, `@std_context`, `@std_initializer` and `@std_call_site`, are unknown attributes outside package `std`, and inside it a misplaced one or one that breaks their rules is this error too (§4.8, D-482, D-692, D-1599, D-1628). One of those rules is that a function must not have both `@std_context` and `@blocking`: a blocking kernel runs on a thread of the blocking pool, which must never receive a fiber's context. In either order, the function keeps `@blocking` and loses `@std_context`, and the diagnostic points at both attributes (§4.8, §10.9, §12.7, D-191, D-819). `@std_initializer(constructor)` names one function of the same module. The function that carries it must return a named type with exactly one type argument, as `context::Key<T>`, and the constructor must have the function's type parameters, with the same bounds, its parameters followed by two `String` parameters, its result type, and a visibility other than `priv` (D-1587, D-1601). `@std_call_site(constructor)` also names one function of the same module. The function that carries it has a body and carries none of `@external`, `@std_initializer` and `@std_clamped`. Its constructor must have the function's type parameters, with the same bounds, its parameters followed by a `String` and two `Int` parameters, and its result type. It must not be `priv`, must exist on every target the function exists on, and must carry neither `@std_call_site` nor `@std_initializer` (D-1630).

Example:

```cheby
@extern(native, "cheby_now")
pub fn now() -> Int

@external(native, "a")
@external(native, "b")
pub fn twice() -> Int

@external(native, "app_store_put")
pub fn put<T: Show>(key: String, value: T) -> Bool
```

Use a known attribute with its documented arguments, once per target:

```cheby
@external(native, "cheby_now")
pub fn now() -> Int

@external(native, "a")
@external(js, "./twice.mjs", "twice")
pub fn twice() -> Int

@external(native, "app_store_put")
pub fn put<T>(key: String, value: T) -> Bool
```
