# E0017: doc comment that documents nothing

A `///` doc comment documents what follows it, which must be a top-level declaration, a variant or field of a type declaration, or a function of an interface declaration (§2.2, D-211, D-227). Only further `///` lines may come between, then the item's attributes. A `///` line after an attribute is misplaced: doc comments come before all attributes (D-434). A `//!` module doc comment must come before the first import or item of the file.

Example:

```cheby
fn area(width: Int, height: Int) -> Int {
  /// The area in square units.
  width * height
}
```

Move the doc comment above the function, or make it an ordinary comment:

```cheby
/// The area in square units.
fn area(width: Int, height: Int) -> Int {
  width * height
}
```
