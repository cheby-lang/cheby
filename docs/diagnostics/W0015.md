# W0015: function calls nested more than three deep

Function calls may nest three deep: `f(g(h(x)))` is fine, and a fourth level is a warning (§13.8, D-1954). A long chain of calls is read from the inside out, against the order in which it runs. A constructor call such as `Ok(…)` or `Circle(…)` adds no level, since it builds data in the shape it is written. A block, a closure, a local function and a `case` start the count again.

There is one warning for each outermost call, at the first call of the fourth level. There is no automatic fix: moving a call out of an argument can change the order in which calls run.

Example:

```cheby
import std::int
import std::io
import std::list
import std::string

fn main() {
  io::println(string::trim(int::show(list::length([1, 2]))))
}
```

Write a pipeline, whose stages run in the order they are read, or bind an inner call to a name:

```cheby
import std::int
import std::io
import std::list
import std::string

fn main() {
  [1, 2]
  |> list::length
  |> int::show
  |> string::trim
  |> io::println
}
```
