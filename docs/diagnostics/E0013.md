# E0013: syntax error

The code does not follow the grammar of Appendix A. The message says what the parser expected and what it found.

Syntax errors that have a rule of their own, such as a line break where a line cannot end (E0014) or an unclosed bracket (E0015), have their own codes. This code covers the rest, for example a missing comma, a keyword in the wrong place, or a form that the grammar does not have, such as a local function with `pub`, a `let` with an `as` message but without `assert`, an empty field list in a variant or pattern like `Foo()` (D-437), a second `as` in a pattern like `A as x | B` (D-438), or type parameters on an interface, as in `interface Into<T>`, which is one error while the rest of the declaration still parses (§8.1, D-165, D-495).

Four cases have a message or help of their own:

- A type declaration without variants, as in `type Empty {}`, is "a type declaration needs at least one variant", with the help "for a type without fields, declare a unit variant, such as `type Empty { Empty }`" (§4.3.1, D-637).
- A path with more than one module qualifier, as in `std::io::println`, gets a help built from the path as written: "import the inner module and qualify with its last name: `import std::io` and `io::println`" (§7.5, D-060, D-637). The segments before the first capitalized one are the modules, or all but the last when none is capitalized.
- A `case` subject after the first that starts with `{`, as in `case n, { 1 } { … }`, is "a `case` subject cannot start with `{`", with the help "put the block in parentheses, such as `({ … })`" (§5.9.6, A.5, D-639).
- A comma after the last `case` subject, as in `case n, m, {`, is "expected a `case` subject after `,`", with the help "remove the trailing comma". The `{` still opens the arms. The parser takes a `{` after a comma for a block subject only when more of the line follows its `}`, as in `case n, { 1 } {` (§5.9.6, A.5, D-639).

In a `case` subject, a type name followed by `{` is not a record construction: the `{` opens the arms, so `case Point { x: 0, y: 1 } { … }` is a syntax error at the `:`, and `case { 1 } { … }` is a subjectless `case` whose first arm lacks its `=>`. Parenthesize a record or a block used as a subject: `case (Point { x: 0, y: 1 }) { … }` (§5.9.6).

Example:

```cheby
fn add(a: Int b: Int) -> Int {
  a + b
}
```

Separate the parameters with a comma:

```cheby
fn add(a: Int, b: Int) -> Int {
  a + b
}
```
