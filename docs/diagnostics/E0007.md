# E0007: reserved word used as a name

Some words are reserved although Cheby gives them no meaning (§2.4, D-128, D-240):

```
if        else      for       while     loop      break     continue
return    mut       impl      trait     struct    enum      match
async     await     macro     self      super     where     yield
go
```

They cannot be used as names. They are reserved so that the compiler can point people to what Cheby uses instead, and so they stay free for later versions, since adding a keyword after 1.0 would break programs (D-075). The help line says what to use: `case` instead of `if` and `match`, recursion instead of loops, `type` instead of `struct` and `enum`, and a fiber in a scope instead of Go's `go`.

The error is reported once, where the word is bound or declared as a name, and uses of that name add nothing. A reserved word used as a name that nothing binds, such as `return(x)`, gets this error where it is used, instead of "cannot find value". Name resolution reports both, so a package with syntax errors gets them only once those are fixed (D-469). Attribute names are not checked, so `@async` is fine (D-435).

A reserved word often causes a syntax error instead, as in `if n > 0 { 1 }` or `return n`. That error (E0013 or E0014) is reported at the word or right after it, and carries the same help line, such as "Cheby has no `if`; use `case`" (D-469). A condition in parentheses, as in `if (n > 0) {`, parses as a call, so the error is at the `{` after the `)`; it carries the help too.

Example:

```cheby
fn next_step(go: Int) -> Int {
  go + 1
}
```

Choose another name:

```cheby
fn next_step(step: Int) -> Int {
  step + 1
}
```
