# E0076: constant whose evaluation exceeded its time or memory limit

Constant initializers run at compile time, and their evaluation is bounded so a runaway constant cannot hang the build (§13.9, D-195). By default each constant may run for 10 seconds of wall-clock time, including the constants it forces, and may keep at most 1 GiB of heap live at once while it runs. The time limit stops a loop at its next function entry or tail call; a single long call into a standard-library kernel finishes first (D-536). The memory limit counts the heap bytes that this one evaluation keeps live at once, the constants it forces and what kernels allocate included. Temporaries that are dropped do not count, and neither do constants evaluated earlier or REPL session values. Every allocation is checked before memory is requested, so a single request over the limit is this error too (D-617). The error points at the constant whose evaluation started at the top level. The message names the limit and its value, as in "evaluating the constant `table` used more than the memory limit of 1GiB", and a note says "the limit counts the heap bytes that the evaluation keeps live at once" (D-617, D-618). When the evaluation was computing another constant that the first one reads, a note names it: "it was computing the constant `x`, which it reads". Constants that read the stopped one are not reported again (D-618).

A package can change the limits in `cheby.toml`, under `[const-eval]`, with `time-limit = "30s"` (an integer followed by `ms` or `s`) and `memory-limit = "2GiB"` (an integer followed by `KiB`, `MiB` or `GiB`).

Example, a computation that never ends:

```cheby
const total: Int = count_up(0)

fn count_up(n: Int) -> Int {
  count_up(n + 1)
}
```

Bound the computation:

```cheby
const total: Int = count_up(0, 1000)

fn count_up(n: Int, limit: Int) -> Int {
  case {
    n >= limit => n
    _ => count_up(n + 1, limit)
  }
}
```
