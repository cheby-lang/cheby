# E0076: constant whose evaluation exceeded its time or memory limit

Constant initializers run at compile time, and their evaluation is bounded so a runaway constant cannot hang the build (§13.9, D-195). By default each constant may run for 10 seconds of wall-clock time, including the constants it forces, and may keep at most 1 GiB of heap live in the build while it runs. The time limit stops a loop at its next function entry or tail call; a single long call into a standard-library kernel finishes first. The memory limit counts the heap bytes live in the build, what kernels allocate included, so temporaries that are dropped do not count (D-536). The error points at the constant whose evaluation started at the top level, and the message names the limit and its value. When the evaluation was computing another constant that the first one reads through a function call, a note names it. Constants that read the stopped one are not reported again.

A package can change the limits in `cheby.toml`, under `[const-eval]`, with `time-limit = "30s"` (an integer followed by `ms` or `s`) and `memory-limit = "2GiB"` (an integer followed by `KiB`, `MiB` or `GiB`).

Example, a computation that never ends:

```cheby
const total: Int = count_up(0)

fn count_up(n: Int) -> Int {
  count_up(n + 1)
}
```

Bound the computation:

```cheby
const total: Int = count_up(0, 1000)

fn count_up(n: Int, limit: Int) -> Int {
  case {
    n >= limit => n
    _ => count_up(n + 1, limit)
  }
}
```
