# E0057: type that nothing in the body determines

Types inside a function body are inferred (§3.12.3), but some constructs need a type that inference has fixed (§3.12.4). This error is reported when such a type is still unknown:

- Field access `x.name` and record update `T { ..base, … }` need the type of `x` or `base` to be known at the point where they are checked, in the order of §3.12.4. Field names are not unique across types, so the compiler does not guess the type from the field name (D-213).
- An operator, an interface call such as `Compare::compare(a, b)`, the `Show` requirement of `{x}` interpolation and a conversion to `dyn` are resolved at the end of the top-level body. If a type they depend on is still unknown then, after numeric literals have been defaulted, it is this error (D-234, D-237).
- A type that nothing in the body fixes at all, such as the element type of `let xs = []` when `xs` is never used as a list of something, needs an annotation too (D-451).

The message names the value whose type is unknown, and the help suggests where to write an annotation, usually on a closure or local-function parameter.

Example:

```cheby
type Point {
  x: Int,
  y: Int,
}

fn main() {
  let get_x = fn(p) { p.x }
  let x = get_x(Point { x: 1, y: 2 })
}
```

The closure is checked before the call that would tell its parameter's type, so `p.x` has nothing to go on. Annotate the parameter:

```cheby
type Point {
  x: Int,
  y: Int,
}

fn main() {
  let get_x = fn(p: Point) { p.x }
  let x = get_x(Point { x: 1, y: 2 })
}
```
