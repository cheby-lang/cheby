# E0051: type with the wrong number of type arguments

A generic type must be given exactly one type argument for each of its type parameters, and a type without type parameters takes none (§3.1, §3.12.1, D-462). Type arguments are never inferred in a written type. Interfaces have no type parameters (D-045), so `dyn Show<Int>` is also an error.

Example:

```cheby
fn first(names: List) -> String {
  "none"
}

fn greeting(name: String<Int>) -> String {
  name
}
```

Give every type parameter an argument, and none to other types:

```cheby
fn first(names: List<String>) -> String {
  "none"
}

fn greeting(name: String) -> String {
  name
}
```
