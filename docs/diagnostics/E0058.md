# E0058: field that the type does not have, or that not every variant has with one type

Field access `x.name` reads a named field of `x`'s type (§5.11.3). It is an error when the type has no field of that name. For a type with several variants, every variant must have the field, and with the same type, because the access works without knowing which variant `x` holds (D-071). The same rule applies to the fields listed in a record update (§5.11.2, D-156).

Tuple elements and positional fields have no names and are read with a pattern instead (D-241).

Example:

```cheby
type Shape {
  Circle { radius: Float },
  Rect { width: Float, height: Float },
}

fn width(shape: Shape) -> Float {
  shape.width
}
```

Only `Rect` has a `width`. Match on the variants with `case`:

```cheby
type Shape {
  Circle { radius: Float },
  Rect { width: Float, height: Float },
}

fn width(shape: Shape) -> Float {
  case shape {
    Circle { radius } => radius * 2.0
    Rect { width, .. } => width
  }
}
```
