# E0058: field that the type does not have, or that not every variant has with one type

Field access `x.name` reads a named field of `x`'s type (§5.11.3). It is an error when the type has no field of that name. For a type with several variants, every variant must have the field, and with the same type, because the access works without knowing which variant `x` holds (D-071). The same rule applies to the fields listed in a record update (§5.11.2, D-156). A record update may name an alias of the type, and an alias of something without named fields, such as a tuple, is this error: "`A` stands for `(Int, Int)`, which has no fields to update" (D-501). A record update names a type with named fields, so an interface and a type parameter are this error too: "`Named` has no fields to update" (§5.11.2).

Tuple elements and positional fields have no names and are read with a pattern instead (D-241).

Cheby has no methods (D-061). A field that is called, as in `xs.length()`, gets a help with the function to call, the receiver first: a function of that name in the module of the type, as "Cheby has no methods; call `list::length(xs)`", else the std function that the name means in another language, as `string::length(s)` for `s.len()`, else the module where the type's functions are. A name close to a field of the type, as `h.handlr(1)` for a field `handler` that holds a function, is more likely a typo of the field, and gets no such help (D-1938).

Example:

```cheby
type Shape {
  Circle { radius: Float },
  Rect { width: Float, height: Float },
}

fn width(shape: Shape) -> Float {
  shape.width
}
```

Only `Rect` has a `width`. Match on the variants with `case`:

```cheby
type Shape {
  Circle { radius: Float },
  Rect { width: Float, height: Float },
}

fn longest_side(shape: Shape) -> Float {
  case shape {
    Circle { radius } => radius * 2.0
    Rect { width, .. } => width
  }
}
```
