# E0044: binding that reuses a name already in scope

Cheby has no shadowing: a name always means one value within its scope (§5.2.3, D-051). A `let`, a parameter or a pattern binding must not reuse the name of an earlier binding in an enclosing scope, a top-level function or constant of the module, or an imported module (D-062). A name bound twice in one pattern, as in `(x, x)`, is this error too, and only this error (§6.2, D-506).

Example:

```cheby
import std::io

fn main() {
  let name = "Ada"
  let name = "Grace"
  let io = "stdout"
  io::println(name)
}
```

Give each binding its own name:

```cheby
import std::io

fn main() {
  let first = "Ada"
  let second = "Grace"
  io::println(first)
  io::println(second)
}
```

The most common case is a local recursive helper whose parameters take the names of the function around it. Rename the outer parameters, and the helper keeps the natural names:

```cheby
fn count_down(initial_n: Int, initial_total: Int) -> Int {
  fn step(n, total) {
    case n {
      0 => total
      _ => step(n - 1, total + n)
    }
  }
  step(initial_n, initial_total)
}
```
