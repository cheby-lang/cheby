# E0042: name that does not refer to anything usable here

A name must refer to something in scope (§7.7). An unqualified name is a local binding or parameter, an item of the current module, a name brought in by an import, or a prelude name. A qualified name `m::x` needs `m` to be an imported module and `x` to be an item of it. A module name is not a value on its own. `Self` names a type only inside an interface declaration, and elsewhere it is reported with this code (§8.1, D-462).

When `m::x` names a standard-library module that has no item `x`, a fixed table of names from other languages gives the help first, so `file::read_text` points to `io::read_file`, `list::size` to `list::length` and `int::from_string` to `int::parse`. An alias is a deliberate mapping, so it wins over the same name in another module: `list::size` does not point to `file::size`, `heap::size` or `map::size` (D-1662). With no alias, the help names up to three other std modules that have an item called `x`, imported or not, as "`std::io` has `read_file`". A name in the module that is close in spelling keeps its "did you mean" before both (D-1658).

Names of other languages get the Cheby form before a close name (D-1934, D-1935): `true` and `false` point to `True` and `False`, `null`, `none` and `undefined` to `None`, `some`, `ok` and `err` to `Some`, `Ok` and `Err`, a bare `println` to `io::println`, `len` to `list::length` and `string::length`, `pass` to `Nil`, and type names such as `Void`, `Vec` and `HashMap` to `Nil`, `List` and `map::Map`. A name that is also a common local name, such as `len` or `ok`, gets its help only where it is called. The alias table holds the names that Rust, Python, JavaScript and Go use for what the tier-1 modules have, such as `string::to_upper` for `string::uppercase` and `list::for_each` for `list::each` (D-1937).

Every module must be imported before use, including standard-library modules (§7.5.2, D-060). `Map`, `Set` and `Bytes` are not in the prelude, so outside their home modules they are named through an import, and the help says which one: "`Map` is not in the prelude: add `import std::map` and write `map::Map`" (§7.6, D-481).

Example:

```cheby
import std::io

fn main() {
  let message = "hello"
  io::println(mesage)
  list::length([1, 2])
}
```

Fix the spelling and import the module:

```cheby
import std::io
import std::list

fn main() {
  let message = "hello"
  io::println(message)
  let n = list::length([1, 2])
  io::println("{n}")
}
```
