# E0061: `case` that does not cover every value

A `case` must have an arm for every value its subjects can have (§6.9, D-022). There is no `if`, so `case` is the only way to branch, and exhaustiveness is what makes it safe: adding a variant to a type points at every `case` that must handle it.

The message lists up to three values that no arm matches, written as patterns, such as `None`, `[_, _, ..]` or `(True, _)`, and says how many more there are. Constructors from other modules are qualified, as in `shape::Circle { .. }` (D-507). An arm with a guard never counts toward coverage, because its guard may be false (§5.9.3). A type whose constructors are not visible here, such as an opaque type from another package, is covered only by `_` or a binding (§4.3.4), and so is `Never` (D-492). When the patterns are too complex to check within the budget, the missing value is `_`, with a note that says so (D-508).

Example:

```cheby
type Color {
  Red,
  Green,
  Blue,
}

fn name(color: Color) -> String {
  case color {
    Red => "red"
    Green => "green"
  }
}
```

Add an arm for every missing value:

```cheby
type Color {
  Red,
  Green,
  Blue,
}

fn name(color: Color) -> String {
  case color {
    Red => "red"
    Green => "green"
    Blue => "blue"
  }
}
```
