# E0066: interface declaration that breaks a rule of interface declarations or embedding

An interface declaration must follow the rules of §8.1 and §8.3:

- Every function mentions `Self` in at least one parameter, so that the satisfying type can be found from the arguments. `fn default() -> Self` is an error in v1 (D-209).
- Interfaces have no type parameters, and interface functions have no type parameters of their own (D-165).
- Function names are distinct within the interface, including the functions it inherits by embedding. An own function with the name of an embedded one is an error even with the same signature (D-505).
- When two embedded interfaces require a function with the same name, the two signatures are identical, and the requirement then counts once.
- Embedding is not cyclic, and only interfaces can be embedded.

Example:

```cheby
interface Named {
  fn name(Self) -> String
}

interface Numbered {
  fn name(Self) -> Int
}

interface Tagged: Named + Numbered
```

`Named` and `Numbered` both require a `name` function, with different signatures, so no type could satisfy `Tagged`. Rename one of them:

```cheby
interface Named {
  fn name(Self) -> String
}

interface Numbered {
  fn number(Self) -> Int
}

interface Tagged: Named + Numbered
```
