# E0053: native symbol of an `@external` that is not defined

A function bound with `@external(native, "symbol")` calls the C function of that name (§12.5, D-030, D-455). When a program runs or is built, every symbol that an `@external` of a reached function names must be defined, and so must the drop function of every reached external type (D-943). If nothing defines one, the program cannot run, and the error points at the `@external` that names the symbol. Every missing symbol is reported, one error each, in the order of the `@external`s that name them (D-532).

A function is reached when the program's code can call it, by the compiler's reach (D-510). A module that holds any reached item is compiled whole, so it may also hold `@external`s that nothing reaches (D-966). Their symbols are not checked: a missing one is bound to a stub that nothing can call (D-943).

Where symbols are looked up depends on the command, and in each the check happens before any code runs or is linked:

- `cheby run`, `cheby test` and the REPL look in the Cheby runtime, then in the native code of each package in build order, then in the `cheby` process itself (D-941). A package's native code is the C files and system libraries that its `[native]` table lists (§12.5.4, D-940).
- `cheby build` looks where the linker will: in the names the runtime exports, then in the package's native code, then in the system libraries that the runtime itself links (D-943). It never reads the linker's messages. A link that fails anyway is a tool error, not this code.

The two differ in one way. `cheby run` also finds symbols of the libraries that the `cheby` program links for itself, which an executable does not link. A program that relies on one runs under `cheby run`, but `cheby build` reports this error. Name the library in `[native]`'s `libraries`, and both commands find it.

`cheby check` does not report this error, because it compiles no C and links nothing (D-532).

Example, in a package whose `cheby.toml` has `targets = ["native"]` and where no library defines `clock_now_ms`:

```cheby
import std::io

@external(native, "clock_now_ms")
fn now() -> Int

fn main() {
  let ms = now()
  io::println("{ms}")
}
```

Check the spelling of the symbol, or supply the code that defines it in the package's `cheby.toml`, as a C file or a system library (§12.5.4, D-940):

```toml
[native]
sources = ["src/clock.c"]
```

A symbol that exists only on some systems needs a function body or an `@external` for each target instead.
