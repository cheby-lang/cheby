# E0079: native foreign result type that holds an external type below its top level

Native foreign code returns a value of an external type only as the function's direct result ([§12.5.1](../spec/12-targets-and-ffi.md#1251-native-abi), D-948). Outside the standard library, an `@external(native, …)` whose result type holds an external type below its top level, such as `Result<Db, String>`, `Option<Db>`, a tuple `(Db, Int)` or a type of your own with a `Db` field, is this error, reported at the `@external(native, …)` attribute.

C code cannot build such a value. A value of an external type is a handle wrapped in a Cheby object whose layout is assigned when the program starts, and C has no way to name it (D-454, D-590). `cheby.h` can build a `Result` or an `Option`, but not the external value inside one ([§12.5.3](../spec/12-targets-and-ffi.md#1253-external-types), D-945). Without this error, the signature would compile, and no C function could implement it.

The rule has three exemptions:

- The standard library is exempt, because its kernels are written in Rust and can build any value (D-948).
- Parameters may hold external types at any depth, as opaque values. C code receives them and may read them through `cheby.h`.
- A type parameter is not checked: a generic foreign function whose result is `Option<T>` compiles even when a call instantiates `T` with an external type.

Example:

```cheby
@external(native, "db_close")
pub type Db

@external(native, "db_open")
pub fn open(path: String) -> Result<Db, String>
```

Return the external value directly from the foreign function, with a second foreign function that reports the error, and build the `Result` in Cheby with a wrapper ([§12.5](../spec/12-targets-and-ffi.md#125-foreign-functions)):

```cheby
@external(native, "db_close")
pub type Db

@external(native, "db_open")
fn open_raw(path: String) -> Db

@external(native, "db_open_error")
fn open_error(db: Db) -> Option<String>

/// Opens the database at `path`.
pub fn open(path: String) -> Result<Db, String> {
  let db = open_raw(path)
  case open_error(db) {
    None => Ok(db)
    Some(message) => Err(message)
  }
}
```
