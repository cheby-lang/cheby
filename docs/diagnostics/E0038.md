# E0038: construct the compiler does not support yet

The compiler is being built in phases (`docs/plan/`), and this is valid Cheby that the current toolchain cannot check or run yet. The message names what is missing, such as "the module `std::process` is not supported yet".

This is not an error in your program (D-451). It is reported once, at the import, and nothing that goes through the import is checked, so it causes no follow-up errors.

The compiler supports every construct of the language. It reports E0038 for one thing only: an import of a standard-library module that the specification or the stdlib plan defines but the toolchain does not ship yet. M2 ships the six tier-2 modules, such as `std::selector` and `std::random`, and the seven tier-1 collections `std::multimap`, `std::sorted_*` and `std::ordered_*` (D-645, D-664). M3 ships tier 3 module by module: `std::time`, `std::net`, `std::file`, `std::url` and `std::http` have shipped, and of tier 3 only `std::process` is left (D-1213). `std::context`, which starts tier 4, stays planned until M4 (D-1049), so the compiler still emits this code for it once tier 3 ships. The rule stays in the compiler for a later tier, and a unit test with a made-up planned module keeps it tested (D-989). Such an import is not an unresolved import (E0039). Paths through it, such as `process::exit`, are not checked and report nothing more (D-480). The examples that import these modules expect this error until the milestone that ships them (D-477).

`cheby check`, `cheby run` and `cheby test` report it the same way, before any code is compiled. The back end no longer emits E0038: since M1, MIR lowering compiles every construct the front end accepts, and a construct it could not compile would be an internal compiler error, not this code (D-554). Earlier M1 builds reported E0038 from `cheby run` for constructs such as `case`, closures and constants that the back end did not compile yet (D-510); none is left.

Example, with a toolchain from before `std::process` ships:

```cheby
//! Needs a tier-3 module.

import std::process

fn main() {
  process::exit(0)
}
```

There is nothing to fix in the program. The code is temporary: when the toolchain ships every planned module, the compiler stops emitting it, and this file stays to say so (D-419, D-451, D-480). The example imports `std::process`, which the toolchain's own probes use since `std::http` shipped (D-729, D-1213). A toolchain that ships tier 3 accepts it.

Types that nothing in a function body fixes, such as the element type of `let xs = []`, are E0057, and a function used on a target where it does not exist is E0067. A name missing from a shipped standard-library module is E0042. All three were reported with this code in early M1 builds (D-480). A bound on a type parameter of a foreign function is E0045 (D-554).
