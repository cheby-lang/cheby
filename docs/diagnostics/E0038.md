# E0038: construct the compiler does not support yet

The compiler is being built in phases (`docs/plan/`), and this construct is valid Cheby that the current toolchain cannot check or run yet. The message names the construct, such as "`case` expressions are not supported yet" or "the module `std::list` is not supported yet".

This is not an error in your program. It is reported once for the outermost unsupported construct, and the rest of that construct is skipped, so it causes no follow-up errors.

Where the construct is decides what else is checked. When it is in a function's body, only the body is skipped: the function's signature is still checked, and calls of the function elsewhere are checked against it, as they would be if the body were supported. When it is in an item's declaration, such as a type parameter, an attribute or a type in a signature, the whole item is skipped, and uses of that item elsewhere are not checked either.

An import of a standard-library module that the specification defines but the toolchain does not ship yet is also reported with this code, not as an unresolved import (E0039). So is a name missing from a standard-library module that is shipped only in part, such as `io::read_line` while `std/io.cheby` has only the printing functions, instead of an unresolved name (E0042).

The code also covers two checks that are not built yet. A type that nothing in a function body fixes, such as the element type of `let xs = []`, needs a type annotation, and it gets its own code later. A function without a body whose `@external` attributes do not cover every target of its module is reported until the cross-target check of §12.6 exists.

Example, while `case` is not supported:

```cheby
fn sign(n: Int) -> Int {
  case {
    n < 0 => -1
    _ => 1
  }
}
```

There is nothing to fix in the program. The code is temporary: when the toolchain supports every construct, the compiler stops emitting it, and this file stays to say so (D-419, D-451).
