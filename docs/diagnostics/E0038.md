# E0038: construct the compiler does not support yet

The compiler is being built in phases (`docs/plan/`), and this is valid Cheby that the current toolchain cannot check or run yet. The message names what is missing, such as "the module `std::fiber` is not supported yet" or "`case` expressions are not supported yet".

This is not an error in your program (D-451). It is reported once for the outermost unsupported construct, and the rest of that construct is skipped, so it causes no follow-up errors.

The front end (`cheby check`) supports every construct of the language. It reports E0038 for one thing only: an import of a standard-library module that the specification or the stdlib plan defines but the toolchain does not ship yet. These are the modules of tier 2 and tier 3, such as `std::fiber`, `std::channel`, `std::duration`, `std::random` and `std::http`, and the tier-1 modules `std::multimap`, `std::sorted_*` and `std::ordered_*`. Such an import is not an unresolved import (E0039). Paths through it, such as `fiber::spawn`, are not checked and report nothing more (D-480). The examples that import these modules expect this error until the milestone that ships them (D-477).

`cheby run` also reports E0038 while the back end is being built. It compiles only the functions and constants that the entry point reaches, and a construct it cannot compile yet in one of them, such as a `case`, a closure or a constant, stops the run with this code before anything runs. Code that `main` never reaches is not compiled, so it never reports E0038 from the back end. Every reachable item is lowered before anything is compiled, so one run reports all of these, after the other diagnostics (D-510). Until constants are evaluated at compile time (E6), `cheby check` checks a constant's type, its restrictions and cycles between constants, and `cheby run` reports E0038 at each constant `main` reaches (D-478).

Examples:

```cheby
//! Needs a tier-2 module.

import std::fiber

fn main() {
  fiber::spawn(fn() { Nil })
}
```

```cheby
//! Checks cleanly; `cheby run` reports E0038 at the `case` until the back end compiles it.

import std::io

fn main() {
  io::println(describe(""))
}

fn describe(text: String) -> String {
  case {
    text == "" => "empty"
    _ => text
  }
}
```

There is nothing to fix in the program. The code is temporary: when the toolchain ships every planned module and compiles every construct, the compiler stops emitting it, and this file stays to say so (D-419, D-451, D-480).

Types that nothing in a function body fixes, such as the element type of `let xs = []`, are E0057, and a function used on a target where it does not exist is E0067. A name missing from a shipped standard-library module is E0042. All three were reported with this code in early M1 builds (D-480).
