# E0006: identifier that breaks the naming convention

The spelling of a name says what it is (§2.3, D-059):

- values, functions, constants, modules and packages are `snake_case`: lower-case letters, digits and `_`,
- types, type parameters, constructors and interfaces are `PascalCase`: an upper-case letter, then letters and digits, without `_`.

A name that starts with a lower-case letter but contains an upper-case letter, or starts with an upper-case letter and contains `_`, is an error. The help line suggests the conventional spelling.

Example:

```cheby
type Shape_Kind {
  Round,
  Square,
}

fn area(rectWidth: Int, rectHeight: Int) -> Int {
  rectWidth * rectHeight
}
```

Use the conventional spellings:

```cheby
type ShapeKind {
  Round,
  Square,
}

fn area(rect_width: Int, rect_height: Int) -> Int {
  rect_width * rect_height
}
```
