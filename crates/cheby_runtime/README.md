# cheby_runtime

The native runtime: memory, the kernels behind the standard library, generic equality, hashing and debug text, panics, and from M2 fibers, channels, scopes, unwinding and IO. It is Rust, built as an rlib, and it exposes a C ABI to generated code. The `cheby` binary links it for the JIT, and [`cheby_rt_exe`](../cheby_rt_exe/README.md) wraps it into the staticlib that executables link (D-928).

## Place in the pipeline

`cheby_runtime` depends on no other `cheby_*` crate. It depends on `mio`, `parking_lot`, `crossbeam-deque`, `crossbeam-utils`, `getrandom`, `libc`, `ryu`, `siphasher` and `unicode-segmentation` (D-730, D-656), and it uses no `wasmtime-internal-*` crate. On targets other than Windows it also depends on `rustls`, `ring` and `webpki-roots`, for TLS (D-1011, D-1036, D-1290).

- **`abi` is the contract with code generation.** It has no state and no dependencies, and is the single source of header bits, tagged-integer encoding, layout ids, string layout, context offsets, exit statuses, panic kinds and symbol names. `cheby_codegen_clif` reads only this module (D-465). `cheby_mir::abi` holds the other half of the contract, the machine signatures.
- **The runtime ID (D-930).** `build.rs` hashes the crate's sources, `build.rs` and `build/`, its `Cargo.toml`, the workspace's `Cargo.lock` and `rust-toolchain.toml`, the target, the features and the cfg values the runtime reads into `abi::RUNTIME_ID`, with SipHash-1-3 128 (`build/runtime_id.rs`, which the `runtime_id_*` tests include too). It writes `$OUT_DIR/runtime_id.rs`, which `runtime_id.rs` includes: the constants and the data symbol `cheby_rt_id$<hex>` that the archive defines once. It also passes the ID to the build scripts of direct dependents as `DEP_CHEBY_RUNTIME_RUNTIME_ID`, which is why the package declares `links = "cheby_runtime"`; nothing is linked through it. `cheby_cli`'s build ID includes it (D-957). The ID changes only when one of those inputs changes, never with an absolute path.
- **Executables** enter through `cheby_rt_main` (`rt_main.rs`, Unix only until M6), which the program object's C `main` calls with the program image (D-925, D-926, D-927). `image.rs` defines the image `cb$image` and the module records `cb$mod$<path>` field by field, versioned by `abi::IMAGE_VERSION`, and `image::install`, the one routine that registers them (D-919, D-920) and then installs the program's constant images into the slots the records name. `consteval/image.rs` defines the constant image (D-979): its bytes, `serialize`, and `install`, which every host calls before `main`, checking the images in one pass and building from the same bytes in a second; the REPL's in-process images (`serialize_in_process`, `install_in_process`) name static objects by address.
- **`cheby_jit`** resolves generated code's imports against `symbols`, the registry every kernel module fills, registers user layouts in `layout` and runs entries through `entry` and `sched`.
- **`cheby_consteval`** uses `consteval`, the constant table and the forcing hook. **`cheby_repl`** reads its prompt through `io::read_input_line`, the one buffered reader of standard input (D-575). **`cheby_driver`** and **`cheby_cli`** create the `Runtime` of a run, a test run or a session (D-690) and read the leak check.
- **`std/`** binds every kernel as `@external(native, "cheby_<module>_<function>")` (D-484). A kernel never calls a Cheby closure, except `map::upsert` through `callback`, and a `@std_context` kernel gets the running fiber's `ctx` first and may suspend or raise (D-692). `net_tls.rs` holds TLS for the HTTP client on targets other than Windows (D-1290), `process.rs` holds `process::exit`'s kernel (D-1293), and `sched/signal.rs` turns SIGINT and SIGTERM into cancellations of `until_interrupted`'s scopes (D-1299).

Rules that hold across the crate:

- Every C-ABI entry point is `extern "C"`, so an internal Rust panic aborts instead of unwinding through JIT frames. A Cheby unwinding inside Rust is a Rust unwinding with a zero-sized marker, caught by a guard at the entry point (D-697).
- `tls.rs` is the only module that declares thread-locals, and every access goes through an `#[inline(never)]` accessor, because a fiber may migrate between threads across a switch (D-686).
- Objects and bytes are counted per accounting domain, and debug builds fail a run with status 102 when objects leak (D-445, D-458, D-691). `CHEBY_RT_POISON=1` poisons freed objects, and `CHEBY_RT_STATS=1` turns on the counters of in-place updates (D-635, D-768).
- A runtime kind that declares a `CustomKind::shape` must describe exactly what its `size` and `children` compute, and a kind with a finalizer or a handle kind declares none. Debug builds check the shape on every free (D-907).
- A fiber suspends only through `park`, which releases the lock it holds after the switch, so no lock, borrow or thread-local pointer lives across a switch (D-687).

## Tests

- Unit tests sit next to the code, and `proptest-regressions/` keeps the failing cases of the property tests of `generic`, `num` and `text`.
- The `models.rs`, `cancel_models.rs`, `select_models.rs`, `park_models.rs`, `retire_models.rs` and `ffi_models.rs` files are `loom` models of the protocols, not of the runtime's code. They build with plain `cargo test -p cheby_runtime`.
- The `dev` profile builds this crate with `opt-level = 2`, so the debug toolchain runs Cheby code on an optimized runtime while the leak check and poisoning stay on.
- `runtime_id_tests.rs` recomputes the runtime ID on temporary copies of its inputs, `image_tests.rs` installs synthetic images and locates return addresses through the call-site map, and `rt_main_tests.rs` runs `cheby_rt_main` with entry thunks written in Rust, re-executing the test binary for closed descriptors and a bad `CHEBY_THREADS`.
- Until M6 the crate builds with stubs on Windows, and entries run on dedicated threads there (D-714).
